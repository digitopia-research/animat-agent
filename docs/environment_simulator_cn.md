# 环境世界模拟器（env_simulator）

> 适用模块：`animat/env_simulator.py`
> 相关模块：`animat/simulator.py`（调试用传感器模拟器）、`animat/sensor_window.py`（感知窗口）

---

## 1. 它解决什么问题

### 1.1 现象：意识流会固着在单一话题上

在一次长跑测试中，用户只问了一句「今天天气如何」，之后 8 小时 45 分钟里，
Animat 的内心独白有 **75% 以上**都在谈天气：

```
13时: 102/111 条提到天气 (91%)
16时: 102/107 条提到天气 (95%)
19时:  94/97  条提到天气 (96%)
```

同一份数据被换着措辞反复咀嚼，直到晚上 20:52 仍未脱离。

### 1.2 根因：外部世界是"静止"的

意识流每轮需要的输入有四个来源，而在长跑场景里它们几乎都不变：

| 输入源 | 状态 |
|---|---|
| 传感器数据 | 电量线性下降，温度恒 37°C，倾角恒 0° |
| 对话历史 | 用户说完一句后长时间沉默 |
| 记忆召回 | 少量、不变 |
| 工具结果 | 唯一"新鲜"的东西，于是被反复咀嚼 |

**真实生物靠外部世界不断变化来打断固着**——有声音、有光影、有人来去。
Animat 的模拟器默认是手动模式，没人按按钮就一个事件都没有。
于是它只能在唯一未完成的事情（"天气查到了但还没告诉用户"）上原地打转。

### 1.3 为什么不能简单"加随机噪声"

一个反直觉的结论：**单纯提高传感器噪声会让情况更糟**。

Animat 曾把恒定的 37°C 正常体温编成"探索系统过热，我快烧起来了"。
如果喂给它一堆无意义的随机抖动，它会转而**为噪声编造解释**——"温度在跳，
我是不是出故障了？""身体在抖，我是不是害怕了？"

**噪声不是信息。** 真实生物需要的是有语义、有结构、会变化的外界。

## 2. 设计思路

### 2.1 定位：环境是"世界"，不是"调试工具"

与现有 `simulator.py` 明确分工：

| | `simulator.py` | `env_simulator.py` |
|---|---|---|
| 角色 | 调试工具 | 世界本身 |
| 行为 | 手动刺激（`/touch` `/hit`）、电量控制、动作回显 | 昼夜节律 + 随机事件持续注入 |
| 是否自动 | 默认手动 | 默认自动 |
| 类比 | 实验室里的注射器 | 户外的天气 |

**独立进程**的意义：将来接真实硬件时，直接停掉它即可，主程序无感知。

### 2.2 通道：复用既有四个传感器话题

```
animat/env_simulator.py
        │
        ├─→ animat/sensor/vision         视觉（有人靠近/离开、光线变化）
        ├─→ animat/sensor/audio          听觉（环境异响）
        ├─→ animat/sensor/touch          触觉（被碰）
        └─→ animat/sensor/interoception  内感（电量/体温/倾角）
```

**完全复用，不新增通道**。`perception.py` 无需任何改动——
它本来就把 payload 原样写入 `SensorWindow`。

### 2.3 原则一：刺激必须有语义

同一个视觉事件，两种呈现方式对模型的影响完全不同：

```
裸数字：  [21:09:39] 视觉: 距离=2.0m, 人脸=有, 凝视=1.0s
带语义：  [21:09:39] 有人靠近到 1.84 米并看向你（距离1.8m, 有人脸）
```

前者要模型自己"猜发生了什么"，后者直接告诉它。
猜的过程就是幻觉的温床。

**实现**：事件 payload 里携带 `event`（机器标识）和 `event_text`（自然语言），
`SensorFrame.to_text()` 优先渲染 `event_text`，同时附上关键读数，
做到"既不给它留想象空间，也不藏起原始数据"。

### 2.4 原则二：内感必须有因果

旧实现里电量匀速下降、体温恒定，这些数字与 Animat 的行为**毫无关联**。

新实现引入**认知负载（cognitive load）**：

```
Animat 说一句话  → 负载 +0.35
Animat 移动身体  → 负载 +0.50
Animat 产生思维  → 负载 +0.12
（无活动时每 2 秒自然衰减 0.08）

负载 → 电量消耗 = 0.05 + 0.15 × 负载
负载 → 体温目标 = 37.0 + 0.8 × 负载
```

于是：

```
它说了很多话 → 电量掉得快、体温升到 37.5°C → 它感知到"我累了"
```

**"我很累"从此有物理前因，而不是凭空编造。**

体温上限锁死在 38.0°C，刻意不越界——越过 40°C 就会触发"过热"叙事，
那是我们要避免的幻觉。

### 2.5 原则三：世界要自洽

事件不是均匀随机的。深夜三点老是"有人靠近"很出戏。

**昼夜节律**驱动环境基调：

| 时段 | 光照 | 底噪 | 人类活动 |
|---|---|---|---|
| 02:00 深夜 | 0.02 | 29dB | 0.05 |
| 09:00 清晨 | 0.27 | 43dB | 0.70 |
| 15:00 白天 | 0.88 | 46dB | 0.83 |
| 18:00 傍晚 | 0.15 | 41dB | 0.60 |

光照用**余弦函数平滑过渡**（而非分段常数），
让 Animat 能看到"天在慢慢变亮"，而不是某一刻突然跳变。

**人类相关事件的权重随时段缩放**：

```python
person_approach 权重 = 0.30 × activity + 0.03
gentle_touch    权重 = 0.12 × activity + 0.01
```

深夜 `activity≈0.05`，靠近事件几乎不会发生；白天则明显增多。
同时事件间隔在深夜自动**拉长 2.2 倍**。

### 2.6 原则四：刺激要稀疏

太密会变成噪声（模型转而解释噪声），太疏则无法打断固着。

提供三档场景密度：

| 场景 | 事件间隔 | 适用 |
|---|---|---|
| `quiet` 安静（仓库） | 7–15 分钟 | 想观察独自思考 |
| `normal` 日常（室内） | 2.5–5 分钟 | 默认 |
| `lively` 热闹（集市） | 40–90 秒 | 压力测试、快速观察 |

## 3. 事件类型

| 事件 | 通道 | 触发内容 | 自然语言描述 |
|---|---|---|---|
| `person_approach` | vision | 距离 0.8–3.0m、检测到人脸、凝视 1–4s | 有人靠近到 X 米并看向你 |
| `person_leave` | vision | 距离 10m、无人脸 | 刚才那个人走开了 |
| `gentle_touch` | touch | 压力 0.05–0.15、电容 0.3–0.8 | 有人轻轻碰了碰你 |
| `light_shift` | vision | 光照 ±0.2~0.4 | 周围光线突然变亮/变暗 |
| `ambient_noise` | audio | 45–70dB、150–900Hz | 远处传来一阵声响（XXdB） |
| `gentle_bump` | intero | 倾角 ±2~4°，2 秒后回正 | 身体被轻碰了一下，晃了晃 |

`gentle_bump` 带 `duration`，会在 2 秒后自动把倾角归零——
模拟真实的"晃一下又站稳"。

## 4. 使用方法

### 4.1 启动

**独立进程，与主程序分开启动**：

```bash
# 终端 1：主程序
cd ~/Workspace/animat-agent
uv run animat

# 终端 2：环境世界
cd ~/Workspace/animat-agent
uv run python -m animat.env_simulator
```

启动后会看到：

```
🌍 环境世界启动 — 日常（室内）
   当前环境: 白天(光照0.57, 底噪46dB, 活跃0.83)
   输入 /help 查看命令，/quiet 暂停事件
env>
```

### 4.2 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `ANIMAT_ENV_SCENE` | `normal` | 场景密度：`quiet` / `normal` / `lively` |
| `ANIMAT_ENV_SEED` | 无 | 固定随机种子，便于复现 |
| `ANIMAT_ENV_BATTERY` | `100` | 初始电量 |
| `ANIMAT_ENV_EVENTS` | `1` | 设 `0` 关闭自动事件（只保留内感上报） |
| `ANIMAT_ENV_LOGLEVEL` | `INFO` | 日志级别 |

示例：

```bash
# 热闹场景 + 可复现
ANIMAT_ENV_SCENE=lively ANIMAT_ENV_SEED=42 uv run python -m animat.env_simulator
```

### 4.3 交互命令

| 命令 | 作用 |
|---|---|
| `/person` | 有人经过（靠近 0.8–3m 并看向你） |
| `/leave` | 人离开 |
| `/touch` | 被轻轻碰一下 |
| `/light` | 光线突变 |
| `/noise` | 环境异响 |
| `/bump` | 身体被碰，倾角晃动后回正 |
| `/status` | 查看当前环境与内感状态 |
| `/scene quiet\|normal\|lively` | 切换场景密度 |
| `/quiet` | 暂停自动事件（内感仍上报） |
| `/lively` | 恢复自动事件 |
| `/help` | 显示帮助 |
| `/quit` | 退出 |

### 4.4 `/status` 示例

```
env> /status
  场景    : 日常（室内）
  事件开关: 开
  环境    : 傍晚(光照0.15, 底噪41dB, 活跃0.60)
  内感    : 电量88.5% 体温37.2°C 倾角0.0° 负载0.24
  已发事件: 7 次，最近: 有人靠近 1.8m @ 21:09:39
```

## 5. 效果预期

### 5.1 应该看到的

- 思维话题**不再长时间固着**：环境事件会自然引入新素材
  （"刚才好像有人经过"「光线变暗了」）
- 电量下降有节奏：说话多的时候掉得快
- 体温轻微波动：忙碌时 37.4–37.6°C，安静时回到 37.0°C
- 深夜思维明显安静，白天更活跃

### 5.2 不应该看到的

- **编造故障**（"系统过热""内存溢出"）——若出现，说明事件语义不够清晰，
  或体温越界（检查是否被人为调高 `ANIMAT_ENV_BATTERY` 之外的因素影响）
- **对每个事件都过度反应**——事件密度过高时模型会疲于解释，
  此时应降级到 `quiet` 场景

## 6. 设计取舍记录

| 决策 | 备选方案 | 为什么这样选 |
|---|---|---|
| 独立进程 | 集成进 `simulator.py` | 环境与世界是不同概念；接真实硬件时可直接停用 |
| 复用既有话题 | 新增 `animat/env/event` | 不引入第二套通路，真实硬件也能用同一套接口 |
| 携带 `event_text` | 只发原始数值 | 数值需要模型猜测，猜测是幻觉的来源 |
| 认知负载驱动内感 | 纯随机波动 | 随机波动会让模型为噪声编造解释 |
| 体温上限 38°C | 允许到 45°C | 超过 40°C 会触发"过热"幻觉叙事 |
| 光照用余弦平滑 | 分段常数 | 让模型看到连续变化而非突变 |
| 事件间隔 2.5–5 分钟 | 每 10 秒一次 | 太密变成噪声，太疏无法打断固着 |

## 7. 与话题饱和机制的关系

`stream_cortex.py` 中还有一层**话题饱和检测**：

- 关键词提取：数字 + 汉字 bigram（过滤虚词）
- 连续 3 轮关键词重合度 ≥ 0.45 → 判定为黏着
- 触发时向 system prompt 注入："你最近几轮一直在想同一件事……换个话题"

这两者是**互补**关系：

| 机制 | 作用方式 | 局限 |
|---|---|---|
| 话题饱和检测 | 被动：发现黏着后提示转向 | 模型"想换"但没素材可换 |
| 环境模拟器 | 主动：持续提供新素材 | 若无饱和检测，可能仍抓着旧话题 |

**只有两者配合，才能真正打断固着。**
若观察到饱和检测频繁触发但话题仍不转移，说明事件密度不足，
应调高 `ANIMAT_ENV_SCENE` 或手动 `/person` `/noise` 注入。

## 8. 后续可扩展方向

当前实现覆盖了"世界在变化"这一层。要继续增强生命感，还可以做：

1. **环境事件写入记忆**
   让"13:20 有人经过"进入情景记忆，后续思维能"回想起"而非仅看到实时数据。

2. **多目标驱力**
   目前只有电量驱动。可增加"无聊"（长时间无新事件 → 探索驱力）、
   "孤独"（长时间无人 → 社交驱力），让内在动机本身就有多个方向。

3. **真实硬件接入**
   停掉 `env_simulator`，把真实传感器数据发布到同样的四个话题即可，
   主程序侧零改动。

4. **场景脚本**
   支持按时间轴编排剧本（如"上午有人来访，下午空无一人"），
   用于观察长期行为演变。
